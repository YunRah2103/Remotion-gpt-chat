# YUNEX V3 extensible modelling and production

User intent: five coding agents can extend shared automotive assets and build editable videos from creative briefs. Preserve PR233, atomic creation, existing catalogues and production workflows. EP003/EP004 are excluded.

Use additive source-first APIs. A model variation records named object edits and actual vertex deformations. Fresh vehicle factories receive edits before animation so private rigs remain registered. Custom components describe box, pipe or loft geometry, replacements, mounting points and limited articulated axes. Raw Three factories remain available. Assemblies compose catalogue parts with real port-to-port pipes; GLB is interchange, source configuration remains canonical.

Recipes accept per-project vehicle/world overrides and custom components, assemblies and supplied word timings. A structured brief compiles explicit creative scene choices to ordinary editable recipes. No narration or timings are synthesized. Plans report absolute frame ranges, preview samples, scene change fingerprints and warnings; render commands can select scenes without changing absolute animation time.

Four silent proofs: turbo V8 connected assembly; sports-car body/interior/aero customisation; modern Formula wing/floor customisation; environment geometry changes with driving. Both orientations, before/after stills, decoded moving MP4s and editable recipes are required acceptance evidence. Missing render evidence must be stated explicitly.

QC distinguishes finite geometry/port checks and broad-phase warnings from visual approval. It cannot claim comprehensive intersection detection, calibrated physics or premium acceptance for every asset. Concurrency uses existing project slugs, non-overwriting creation and normal fast-forward Git updates.
