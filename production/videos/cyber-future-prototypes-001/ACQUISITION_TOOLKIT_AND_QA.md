## Creative constraints learned from earlier YUNEX films
- Target **real, physically manufactured futuristic prototype vehicles**: dramatic cyberpunk atmosphere, premium wide/portrait cinematography, real rolling/driving vehicle preferred, highly recognisable design. Distinguish real driving, physical static show car filmed by moving camera, studio turntable, and digitally generated renders. CGI / video games / AI-generated vehicles are NOT approved.
- **Do not source only static press stage walkthroughs:** target 8–12 genuinely distinct moving camera scenes per worker, preferably at least 5 strong clips over 2 physically real models. Prioritise strong 2–5s clean hero shots suitable for first large reveal after the music lifts at ~6.75s. Give user honest PARTIAL if insufficient real motion exists.
- Full-bleed native landscape and full-bleed native portrait sources are accepted. Real original dimensions: landscape >=1920x1080 / portrait >=1080x1920, maximum preferred 4K. A 1920x1080 landscape source yields only ~608x1080 pixels in a centred portrait crop: DO NOT certify it as native 1080x1920. Reject 720p upscales, embedded black bars, overly compressed sources, obstructive watermarks, poor vehicle framing, repeated perspectives.
- The final soundtrack is **the user's exact ~21.08 second uploaded MP3**, NOT stored in GitHub. Footage agents DO NOT mix sound or create the final edit; preserve usable original vehicle audio where possible. Do not invent audio availability.
- Every clip needs actual video bytes, source attribution, owner/publisher, original URL, true physical model/variant, filming type, view angle, native resolution/FPS/codec/bitrate, exact in/out, SHA256, genuine decoder-verified screenshots and manual cinematic review. A platform or test video "works" does not mean its target model/video has been acquired.

## Actual tools available — inspect existence on the branch before invoking
**A. Manufacturer originals and direct MP4/MOV (FIRST PRIORITY):**
- Search original video libraries and downloadable press/B-roll media from Audi, BMW PressClub, Hyundai, Renault/Alpine, Stellantis, Lotus, Porsche, Mercedes, Lamborghini, and approved filmmakers.
- Use `curl --fail --location --retry 2`, `wget`, or a short Python streamed HTTPS downloader for an actual *direct media* URL; check HTTP response/content-type and magic bytes before identifying as video. This has worked on GitHub runners.
- Preserve highest genuine available source resolution, preferably true 2160p / 4K. Avoid uncontrolled repeated recompression.

**B. Multi-engine extractor (available on main):**
- `production/footage_rescue/acquire.py`; `production/footage_rescue/README.md`; workflow `.github/workflows/footage-rescue.yml` on `main`. Existing extractor supports TikTok, Instagram, YouTube and Dailymotion.
- `yt-dlp` native first; `yt-dlp --impersonate chrome` (requires supported curl-cffi setup) second; `gallery-dl` for TikTok/Instagram where appropriate; `pytubefix` optional YouTube experiment; `ffmpeg` for extracting/remuxing. Check actual current implementation and dependencies, do not invent CLI flags.
- Experimentally improved X/Twitter, Pinterest, Twitch, Snapchat and Bluesky support, plus bounded fallback/retries, lives on `feature/footage-rescue-multisource-20261011` with `production/footage_rescue/acquire.py` and `LIVE_PLATFORM_AUDIT_2026-10-11.md`. **This extension was not verified merged into main**. Inspect exact ref before using or selectively porting; do NOT merge other agents' work blindly.
- **YouTube repeatedly failed direct downloading on GitHub-hosted Linux/Windows/macOS runners** due login/bot checks despite many yt-dlp clients, Piped/Invidious, etc. Useful for finding official video names but NOT a dependable acquisition source. Two bounded failed attempts, then pivot to publisher originals or accessible social posts.
- **TikTok and Instagram** succeeded on selected true 1080x1920 or 1088x1936 automotive media but also returned 576x1024/720x1280 and some blocked links. Independently verify per source. These are the strongest tested vertical social options, not guaranteed full quality.
- **X/Twitter and Pinterest** extraction worked on tested posts but tested best sources were 720-class, usually below our HD gate; use for discovery and only accept if a specific media stream actually passes FFprobe 1080p.
- **Twitch** downloaded 1920x1080 gaming/sim-racing footage; **not suitable for authentic physical prototypes** unless actual real camera footage can be proven. Snapchat sample 540x960 (too low), Bluesky mixed/720p, Dailymotion transport sometimes works but sample quality 480p, Facebook Reels and Reddit unsuccessful on GitHub-hosted tests. Do not waste time.
- Do not restart Pixbay/Pexels API-secret troubleshooting or repeatedly retry blocked Vimeo/YouTube. Existing `production/footage_finder` can help discover footage but often lacks model precision for rare physical prototypes.

**C. Video verification and package transport:**
- `ffprobe -v error -show_streams -show_format -of json FILE`; `ffmpeg` decode frames / inspect temporal footage and cuts; ffmpeg trims with stream copy when possible; reencode only when a genuine output cut requires it. Use PySceneDetect if installed for candidate scene breaks; use SHA256 for exact-source verification and comparison of decoded frames for repeated viewpoints.
- Render real contact sheets / timed screenshots for EVERY selected clip. Verify car identity, whether vehicle actually travels, proportion of visible frame and 9:16 crop suitability. A label like "Concept C" doesn't prove footage features that model, or that a clip is real footage instead of CGI.
- **GitHub Actions artifacts** work as large-file transport: run a branch-scoped workflow that downloads, ffprobes/decodes, packages actual MP4/MOV clips plus manifest/contacts, and calls `actions/upload-artifact`. Return exact run URL, artifact ID, expiry, SHA256 and media count. A passing workflow with diagnostics-only ZIP is a FAIL for footage gate.
- ONE ZIP per agent: `CYBER-FUTURE-001-FOOTAGE-[LETTER]` with `clips/`, `manifest.json`, `manifest.csv`, `contact_sheets/`, `README_START_HERE.md`, `rejections.json`. Distinct original real moving angles, not 12 slices from one identical shot. If original video big, archive enough genuine native-quality segment handles and the source original hashes.
- Do not overwrite others' source material. Mark source claims + model coverage in issue #32. Only the director merges four worker ZIPs into a single cross-agent-deduplicated footage master when the actual artifacts are available. Editor/sound/manager agents start after that.
